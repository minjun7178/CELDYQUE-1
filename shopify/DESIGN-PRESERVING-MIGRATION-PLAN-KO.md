# 기존 디자인 유지 Shopify 이식 계획

작성일: 2026-10-30. 계획 문서이며 이 문서 작성으로 테마를 업로드하거나 배포하지 않는다.

## 목표와 범위

CELDYQUE의 기존 레이아웃, 색상, 폰트, 이미지, 제품별 상세 구성, FAQ와 모션을 유지한다. 구매 동작은 Shopify 상품 폼, 장바구니와 호스팅 결제를 사용한다. 로그인·계정·주문 조회는 이미 연결한 Shopify 고객 계정을 사용한다. Horizon에 디자인을 맞추지 않는다.

현재 카탈로그 기준 활성 제품은 14개다. 오래된 HTML 파일이나 임시 페이지를 별도 판매 제품으로 자동 등록하지 않는다. 홈페이지, Products 목록, 활성 상품 14개, About, FAQ, Contact와 기존 콘텐츠 페이지를 먼저 목록화한다. 기존 외부 판매처 링크는 구매 CTA 교체 대상과 구분하며 일괄 삭제하지 않는다. 실제 문의 전송 경로는 목적지 확인 전 활성화하지 않는다.

## 현재 상태

- 별도 worktree / `codex/shopify-liquid-pilot` 브랜치에서 작업한다.
- 대상은 `celdyque-dev-test.myshopify.com`의 미게시 테마 `189650600047`이다. 기존 홈페이지, main, DNS는 변경하지 않는다.
- ArbutXA 한 제품의 원본 HTML/CSS를 옮겼고, `form 'product'`를 사용하는 Add to cart 버튼이 있다. Shopify 테스트 결제와 고객 주문 조회까지 검증했다.
- 현재 빌더는 ArbutXA HTML을 고정 추출하고, dev 홈페이지도 같은 상품을 보여준다. 다른 상품으로 확장하기 전에 이 고정을 해제해야 한다.
- Amazon 앱은 설치 전 본인 인증 단계에서 보류 중이다. 실제 Amazon 재고와 연결되지 않았으며 Shopify 자동 주문 처리는 꺼져 있다.

## 버튼의 의미

1. 기본 Add to cart: Shopify의 상품 폼과 실제 variant ID를 사용하되 모양은 현재 검은색 구매 버튼을 유지한다. 단순 링크를 바꾸는 방식으로 가격·재고를 구현하지 않는다.
2. 바로 구매: 필요하면 Shopify가 생성하는 `payment_button`을 구매 영역에 추가한다. Shop Pay 등 표시와 이용 가능 여부는 실제 결제 설정·방문자 환경에 따라 달라지며 특정 결제수단 노출을 보장하지 않는다.
3. 장바구니: 기존 디자인과 어울리는 테마 화면에서 Shopify 장바구니 데이터를 표시한다. 결제 버튼은 Shopify checkout으로 이어진다.
4. 결제·로그인·주문 조회: Shopify 호스팅 화면을 사용한다. 상품 페이지의 CSS가 해당 화면까지 그대로 적용되는 것은 아니다.

## 진행 순서와 검토 결과물

### 1. 원본 기준과 대응표

페이지별 화면·이미지·스타일·동작을 기록한다. 기존 URL → Shopify 페이지/상품 경로 대응표를 작성한다. 현재 파일과 승인된 영문 원고 사이의 차이는 임의로 재작성하지 않고 확인 대상으로 남긴다. 변경 전 테마와 코드를 보존한다.

### 2. 공통 구조와 대표 페이지 두 개

헤더·푸터·폰트·기본 CSS를 공통화하고 원본 main 영역을 옮긴다. 제품마다 다른 상세 배치는 각 제품의 snippet/section으로 유지한다. 공통화 때문에 모든 상세 페이지를 ArbutXA 레이아웃으로 바꾸지 않는다.

ArbutXA와 PDRN 세럼을 기준으로 원본/Shopify 비교 화면을 만든다. 이름·가격·상품 ID·구매 가능 여부는 Shopify 상품 데이터와 연결한다. 승인된 성분·사용법·근거 내용은 제품별 자료를 사용한다. 필요 항목만 metafield로 분리하고 모든 문구를 테마 편집기로 옮기는 작업은 이번 범위에 포함하지 않는다.

### 3. 나머지 제품과 사이트 페이지 확장

검증된 변환 규칙을 나머지 12개 제품에 적용한다. 이미지 경로, CSS 충돌, 제품별 FAQ/모션, 중복 DOM ID를 점검한다. 홈페이지·Products 목록·소개·FAQ 페이지와 메뉴/검색을 연결한다. Shopify로 옮긴 내부 페이지의 링크가 원래 홈페이지로 빠져나가지 않게 한다. 미이식 페이지와 외부 판매처는 명시적으로 구분한다.

가격·SKU·재고·중량은 임의의 실데이터를 만들지 않는다. 테스트 값은 분리 표시하고 Amazon SKU는 확인 전 비워 둔다. 상품 handle 기반 대응표를 사용해 정식 스토어로 옮길 때 달라지는 product/variant ID를 하드코딩하지 않는다.

### 4. 구매 동작과 시각 검증

데스크톱·모바일에서 원본과 비교한다. 상품별 올바른 항목 담기, 혼합 장바구니, 수량 수정·삭제, 새로고침 후 유지, 품절·재고 초과 처리, 테스트 checkout, 고객 로그인 및 주문 조회를 확인한다. 테스트 주문은 실제 출고 대상으로 보내지 않는다. 대표적인 레이아웃 차이를 먼저 고치고 전체 상품 링크를 검사한다.

### 5. 성능과 검색 정보

Liquid는 서버에서 HTML을 생성하지만 원본 이미지·CSS·JS 비용을 자동으로 없애지 않는다. 기존 사이트도 정적 HTML이므로 이식만으로 속도 향상을 보장하지 않는다.

이미지는 적절한 크기로 Shopify CDN에서 제공하고, 첫 화면 주요 이미지는 즉시 로딩하며 하단 이미지는 지연 로딩한다. 페이지에 필요한 스타일과 스크립트만 불러온다. 제품 정보가 JavaScript 실행을 기다리지 않도록 한다. Theme Check 및 대표 페이지 모바일 성능을 측정하고 원본과 비교한다.

고객용 본문, 메타 정보, 제품 구조화 데이터의 일치를 점검한다. Shopify의 structured_data와 기존 JSON-LD가 중복되지 않게 한다. dev는 비밀번호 보호와 noindex를 유지한다. 정식 이전 시 기존 .html URL의 301 리디렉션, canonical, 사이트맵과 색인 설정을 별도로 검증한다.

### 6. 정식 스토어 이전 — 현재 수행하지 않음

현재 Dev Dashboard dev store는 테스트 전용이며 판매용 전환이 불가능하다. 정식 판매 스토어에 완성된 테마와 상품·콘텐츠를 옮긴다. 계정·결제·배송·앱 연결은 스토어별로 다시 설정하고 검증한다. 실제 판매가·배송비·정책·MCF 연결은 확정 자료와 대표자 인증 후 적용한다. 테스트 주문/고객/임시 재고는 운영 데이터로 이관하지 않는다. 운영 도메인 변경과 공개는 사용자 승인 후 별도 단계로 진행한다.

## 작업량 판단

파일 복사 자체보다 공통화, Shopify 경로/상품 데이터 연결, 제품별 시각 비교와 구매 검증에 시간이 든다. HTML/CSS를 재사용하므로 새 디자인 제작은 필요 없다. 대표 두 페이지와 공통 구조를 먼저 완성한 뒤 반복 적용한다. 검토 전 픽셀 단위 동일성이나 더 빠른 로딩을 약속하지 않는다.
