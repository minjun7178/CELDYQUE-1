# CELDYQUE 자료 구조·콘텐츠 실행 계획

작성일: 2026-10-12 (Asia/Seoul)
기준 조사: [현재 자료·콘텐츠 현황](content-audit-2026-10-12.md)
상태: 향후 작업 계획. 아래 폴더·데이터 구조·가이드 URL은 제안이며 아직 구현·배포하지 않았다.

## 1. 목표와 이번 결정

제품은 유지하고 디자인은 나중에 교체한다. 먼저 14종의 정확한 제품 기준 정보와 근거를 정리한 뒤, 고객이 제품을 이해하고 선택하는 데 필요한 원고를 만든다. SEO와 AEO를 별도 문서 생산 공정으로 나누지 않는다. 자료와 원고는 함께 관리하고, 검색 유입과 AI 언급·인용은 구분해서 측정한다.

이번에 생성한 것은 현황 문서와 이 계획서다. 제품 원본 14개, 새 가이드, HTML 생성기, 계정 설정은 아직 만들거나 변경하지 않았다.

작업 기본값:

- 기존 14제품과 기존 제품 URL을 유지한다. 상품 추가·삭제·가격 변경은 이 계획에 포함하지 않는다.
- 현재 영문 사이트를 기준으로 공개 원고는 영어, 작업용 설명·검토 의견은 한국어로 관리한다.
- 한국어 사이트 또는 다른 시장용 원고는 타깃 시장 확인 후 별도 결정한다. 한국어와 영어 페이지를 무작정 복제하지 않는다.
- 특정 AI의 추천 순위나 인용을 보장하지 않는다. 공개되지 않은 가중치·점수를 가정하지 않는다.
- 레이아웃을 바꾸기 전에 자료를 정리한다. 승인된 사실 오류 수정과 콘텐츠 반영은 디자인 개편과 별도 변경으로 검토할 수 있다.

## 2. 자료의 네 단계

```text
원본 근거: 패키지·제조사 사양·시험 자료·공식 판매처 자료
    ↓ 항목별 출처와 적용 범위 확인
제품 기준 정보: 14제품 각각의 이름·성분·함량 의미·사용법·주장
    ↓ 확인된 사실을 바탕으로 편집
콘텐츠 원고: 제품별 설명·FAQ + 제품군 비교·공통 가이드
    ↓ 공개 승인된 내용만 반영
공개 페이지: 제품·Shop·FAQ·가이드·검색 데이터·JSON-LD
```

### 근거 자료

공식 라벨·제조사 자료는 제품의 구성과 표시 내용을 확인하는 데 사용한다. 원료 연구와 완제품 시험은 별개로 분류한다. 완제품 시험도 대상 제품·시험 방법·대상자·기간·측정 결과의 범위 안에서만 설명한다. 일반 성분 연구를 그대로 자사 완제품의 효과나 우월성으로 옮기지 않는다.

기존 홈페이지는 `과거에 무엇을 게시했는지`를 확인하는 자료다. 패키지·제조사의 최신 사실을 확정하는 원본을 대신하지 않는다. 자료끼리 충돌하면 임의로 최신처럼 보이는 문구를 선택하지 않고 제품 버전·시장·자료 작성일을 확인한다.

### 내부 자료와 공개 자료

내부 제품 기준 정보는 고객에게 그대로 노출하는 페이지가 아니다. 제품별 사실·근거·상태를 관리하는 원본이다. 공개 원고는 그중 확인되고 게시 가능한 정보로 작성한다.

원가·제조사 계약·미공개 처방·개인정보·비공개 시험 원본은 접근이 제한된 별도 저장소에 둔다. Git 저장소가 공개라면 `docs/`에 넣는 것만으로 비공개가 되지 않는다. `assets/`·`images/`·`videos/`·`partials/`는 현재 전체 복사 배포되므로 내부 자료를 보관하지 않는다.

## 3. 제안하는 저장 구조

현재 정적 사이트를 유지하면서 다음 구조로 확장한다. 새 프레임워크나 CMS 도입을 선행 조건으로 삼지 않는다.

```text
docs/
  content-audit-2026-10-12.md       # 현황·원문 아카이브
  content-plan-2026-10-12.md        # 이 계획서
  content-review-log.md            # 항목별 변경·검토 기록(예정)

content/                          # 개발용 원본, 직접 배포하지 않음
  brand.json                      # 브랜드·연락처·공식 계정
  products/
    pdrn-25.json                   # 제품 사실·근거 참조·상태
    pdrn-12-egf.json
    pdrn-12-egf-cream.json
    ...                           # 운영 14종
  retailers.json                  # 판매처·지역·추적 링크
  evidence-index.json             # 공개 가능한 근거 메타데이터만
  copy/en/
    products/<product-id>.md      # 제품별 공개 원고
    guides/<guide-id>.md          # 비교·선택·사용 가이드
    faq.json                      # 질문 ID·답변·담당 페이지
  media.json                      # 사진·영상의 대상·권리·설명

<접근 제한된 별도 자료실>/
  packaging/
  manufacturer/
  finished-product-studies/
  ingredient-studies/
```

JSON을 사용하는 이유는 이름·수치·링크를 검사하고 HTML에 재사용하기 쉽기 때문이다. 긴 설명과 원고는 Markdown으로 작성한다. 초기 검토는 MD 표로 보여주되, 제품 수치의 최종 관리 원본을 MD와 JSON에 각각 따로 두지 않는다. 향후 CMS나 다른 프레임워크로 이전하더라도 같은 제품 ID와 데이터를 유지한다.

이 구조는 아직 구현되지 않았다. 현재 `build_site.py`가 `content/`를 해석하지도 않으므로, 파일만 생성해 놓고 공개 페이지가 자동으로 갱신된다고 생각하면 안 된다.

## 4. 제품별 기준 정보의 필드

| 묶음 | 항목 | 규칙 |
|---|---|---|
| 식별 | `product_id`, 공식명, 짧은 이름, 별칭 | 제품 ID는 이름·디자인·URL 변경과 독립적으로 유지 |
| 상태 | active/upcoming/retired, 적용 시장·언어·처방 버전 | Retinal 등 미운영 파일을 운영 제품과 분리 |
| 주소 | 기존 URL, canonical, 이전 URL | 현재 주소 보존. 변경은 대응표 작성 후 처리 |
| 기본 규격 | 용량·단위·패키지 형태·제품 유형 | 패키지 표기를 그대로 기록하고 단위를 별도 저장 |
| 성분 | 전체 INCI 순서, 주요 성분, 성분별 표기명 | 주요 성분 묶음과 전성분을 구분 |
| 농도 | 표시 수치·단위·대상 물질·배합 기준·설명 | 복합 원료 투입률과 활성 성분 함량을 별도 필드로 관리 |
| 사용 | 부위·양·순서·빈도·혼합 여부·씻어냄 여부 | 제조사/라벨 근거. 모든 제품에 같은 사용법을 복제하지 않기 |
| 주의 | 사용 제한·보관·유통/개봉 후 기간 | 제품별 라벨 확인. 모르는 값을 보편적 수치로 채우지 않기 |
| 특징 | 제형·마무리감·기능 설명·비교 가능한 차이 | 측정 결과, 브랜드 설명, 소비자 경험을 구분 |
| 주장 | 효능·시험·인증·원산지·무첨가 관련 문구 | 주장별 증거·한계·승인 문구를 저장 |
| 판매 | 판매처·ASIN·정상 상품 URL·Attribution URL | 단품/세트 구분. 추적 URL을 임의 정리하지 않기 |
| 근거 | 근거 ID·문서 위치·발행/검토일·적용 버전 | 중요한 수치·주장·사용법은 항목 단위로 연결 |
| 미디어 | 대표·앞면·뒷면·라벨·제형·사용 영상 | 실제 제품 사진과 콘셉트 이미지를 구분 |
| 검토 | 작성자 역할·검토자 역할·상태·실제 검토일 | 이름·날짜를 임의로 만들어 권위를 부여하지 않기 |

### 항목별 상태

| 값 | 뜻 | 공개 원고에 사용하는 방식 |
|---|---|---|
| `imported` | 현재 사이트에서 수집한 문구 | 작업 기록에 보존. 사실 검증으로 취급하지 않음 |
| `needs_verification` | 근거가 없거나 불명확함 | 새 주장을 확정해 쓰지 않고 질문 목록에 둠 |
| `conflicting` | 출처나 페이지 사이에 차이가 있음 | 제품 버전·시장 확인 후 해결 |
| `verified` | 근거와 일치함을 확인함 | 공개 가능 여부와 표현 검토를 거친 뒤 사용 |
| `approved` | 공개 문구까지 검토됨 | 페이지·FAQ·카드·JSON-LD에 재사용 |
| `retired` | 이전 버전 또는 폐기된 문구 | 이력 보존, 새 출력에서 제외 |

공개 가능 여부(`public/internal/restricted`)와 검토 상태는 별개다. 사실로 확인된 내부 문서라도 자동 공개하지 않는다. 기존 페이지에 남은 미검증 문구는 우선순위 목록으로 관리하며 새 생성기로 그대로 확산시키지 않는다.

### PDRN 농도 항목의 기록 예시

아래는 데이터 형식의 예시다. 12%의 의미를 확정한 제품 사양이 아니다.

```json
{
  "product_id": "pdrn-12-egf",
  "current_url": "/product-pdrn-12-egf.html",
  "concentration": {
    "observed_labels": ["PDRN 12%", "120,000 ppm PDRN complex", "PDRN 120,000 ppm"],
    "substance": null,
    "basis": null,
    "verified_value": null,
    "evidence_ids": [],
    "status": "conflicting",
    "question": "복합 원료의 배합량인가, PDRN 자체 함량인가? 적용 처방과 라벨은 무엇인가?"
  }
}
```

빈 값은 `null`로 남긴다. `0`, 일반 성분 지식, 숫자 환산 결과로 누락된 제조 사실을 채우지 않는다.

## 5. 근거·FAQ·미디어의 별도 관리

### 근거 목록

각 근거에 `evidence_id`, 자료 유형, 발행 주체, 원본 보관 위치, 적용 제품·버전·시장, 발행일, 확인일, 공개 범위, 뒷받침하는 주장, 뒷받침하지 못하는 주장을 기록한다. 비공개 원본은 공개 웹페이지에 직접 링크하지 않는다. 공개 가능한 시험 요약을 별도로 승인받아 게재하는 방식은 가능하다.

### FAQ

질문마다 고정 `question_id`, 실제 질문 문구, 적용 제품, 짧은 답, 상세 답을 담당할 페이지, 근거 ID, 검토 상태를 둔다. 같은 답을 여러 파일에 각각 수정하지 않는다. 제품 상세는 제품 사용 질문, 공통 FAQ는 구매·보관·제품군 안내, 비교 가이드는 선택 기준을 담당한다.

모든 제품의 FAQ를 기계적으로 같은 개수로 채우지 않는다. 고객에게 실질적인 질문만 작성하고, 같은 질문의 변형을 여러 페이지로 대량 생성하지 않는다.

### 미디어

`asset_id`, 원본 경로, 파생 파일, 연결 제품, 촬영 대상, 권리/출처, 대표 용도, alt, 실제 공개일(알려진 경우), 영상 길이·음성·자막 여부를 기록한다. Git 날짜를 촬영일·최초 공개일로 쓰지 않는다. 라벨 사진의 글자와 전성분 텍스트를 대조하는 작업은 이번 조사 다음 단계다.

## 6. 공개 페이지의 정보 구조

```text
Home
 ├─ Products / 기존 Shop
 │   └─ 제품 상세 14종
 │       ├─ 제품별 성분·사용법·핵심 FAQ
 │       └─ 관련 비교·선택 가이드 링크
 ├─ Guides / 정보가 충분해질 때 추가할 안내 목록
 │   ├─ PDRN 3종 비교
 │   ├─ Volufiline 사용·표시 의미
 │   └─ 필요한 제품군 안내
 ├─ FAQ / 구매·보관·제품군 질문의 공통 진입점
 ├─ About / 회사·브랜드·근거가 있는 철학
 ├─ Where to Buy / 실제 판매처
 ├─ Contact
 └─ Brand Film
```

제품 상세의 기본 내용 순서는 다음과 같다. 레이아웃을 강제하는 설계가 아니라 원고의 항목 순서다.

1. 공식 제품명·용량·제품 유형·간결한 요약.
2. 선택에 필요한 실제 특징과 확인된 차이 3~5개 이내.
3. 제형·사용 단계·사용법·주의사항.
4. 주요 성분과 농도 의미, 펼쳐볼 수 있는 전성분.
5. 근거가 있는 제품 주장과 그 범위.
6. 관련 제품 비교로 이동하는 링크.
7. 제품별 핵심 FAQ.
8. 정확한 외부 구매 링크와 관련 지원 정보.

설명 분량을 일률적으로 맞추지 않는다. 첫 답변은 질문에 직접 답하고, 조건·근거·한계를 이어 설명한다. 제품명과 수치의 대상이 문장만 읽어도 명확하도록 쓴다. 표나 FAQ를 넣는 행위 자체가 AI 가산점을 보장하는 것은 아니다.

접이식 탭·FAQ를 사용해 화면을 간결하게 만들 수 있다. 내용은 HTML에 포함하고 사용자가 실제로 열어볼 수 있게 한다. 별도 가이드는 관련 제품과 FAQ에서 정상 링크로 연결한다. 사용자에게 접근 경로가 없는 봇 전용 문구나 영구 숨김 텍스트를 만들지 않는다. 공개 본문과 JSON-LD는 같은 사실을 설명해야 한다. [Google 숨김 콘텐츠 정책](https://developers.google.com/search/docs/essentials/spam-policies#hidden-text-and-link-abuse), [구조화 데이터 지침](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)

## 7. 14제품별 작성 범위와 묶음

아래 특징은 현재 사이트에 있는 주제이며 검증된 효능 목록이 아니다. 원고를 확정하기 전에 근거를 확인한다.

| 제품 ID | 제품별로 정리할 핵심 | 연결할 공통 콘텐츠 |
|---|---|---|

## 8. 중복·불일치를 없애는 구현 계획

현재 제품 정보는 HTML·Shop·검색·FAQ·JSON-LD에 흩어져 있다. 다음 단계에서 작은 생성/검증 도구를 추가하는 방안을 우선 검토한다.

1. 제품 사실과 짧은 표시명·검색 별칭·이미지·링크를 제품 기준 JSON에서 관리한다.
2. 승인된 제품/FAQ 원고를 Markdown 또는 FAQ 데이터에서 관리한다.
3. 빌드 시 제품 데이터로 Shop 카드·검색 카탈로그·Product JSON-LD를 만들고, 원고로 공개 HTML을 생성한다.
4. 브라우저가 실행되기 전에 핵심 본문을 읽을 수 있는 정적 HTML을 유지한다.
5. 초기에는 기존 레이아웃을 그대로 사용한다. 생성기를 적용하기 전에는 변경 대상 파일 목록으로 수동 동기화하고 검사한다.
6. 새 디자인은 같은 제품 데이터와 원고를 다른 템플릿으로 표시한다.

JSON-LD는 검증된 사실의 표현이며 공개 콘텐츠를 대체하지 않는다. 실제 가격·재고·리뷰 정보가 없는 상태에서 Offer·평점 등을 채우지 않는다. Google AI 검색에 필수라는 이유로 `llms.txt`나 별도의 AI 전용 스키마를 선행 작업으로 만들지 않는다. [Google AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features)

## 10. 현재 가장 먼저 받을 자료

한 번에 모든 자료를 요구하기보다 PDRN 3종으로 시작한다.

1. 각 제품의 현재 판매 패키지 앞면·뒷면·사용법·전성분이 읽히는 원본.
2. PDRN 25%/12%가 무엇의 비율인지 설명하는 제조사 자료, 적용 시장/버전.
3. 실제 제품별 사용량·혼합 여부·사용 빈도·주의사항.
4. 제품 효능·무향·인증·원료 출처 등을 게시하려면 해당 근거.
5. 이미 연결된 Search Console의 기존 속성에서 페이지 색인·사이트맵·검색 실적 확인. 새로 연결했다고 가정해 중복 설정하지 않기.

이후 같은 자료를 나머지 제품에 확장한다. 비밀번호 공유 대신 기존 계정의 적절한 접근 권한이나 필요한 보고서를 활용한다. 타깃 판매 국가·주요 언어·공식 브랜드 표기·검토 담당도 시작 단계에서 확인한다.

## 11. 검증과 디자인 이전 시 보호할 항목

### 자료 검사

- 제품 ID·기존 URL·ASIN 14종이 서로 일대일로 연결되는가.
- 농도에 대상·단위·기준이 있고 근거 없는 값은 미확인으로 남아 있는가.
- 전성분은 최신 패키지·시장·처방 버전과 맞는가.
- 사용법과 주의가 제품 상세·FAQ·가이드에서 충돌하지 않는가.
- 원료 연구·완제품 시험·마케팅 표현이 구분되는가.
- 공개 문구만 출력되고 비공개 파일은 배포에 섞이지 않는가.

### 페이지 검사

- 제목·설명·canonical·본문·이미지 설명·JSON-LD가 같은 제품을 가리키는가.
- 기존 URL과 추적 파라미터, 질문 앵커와 내부 링크가 유지되는가.
- 새 가이드는 관련 페이지에서 접근 가능하고 사이트맵에 정확하게 반영되는가.
- 접이식 FAQ는 키보드·모바일에서 열리며 핵심 내용이 정적 HTML에 있는가.
- 새 이미지·폰트·레이아웃 때문에 본문 읽기·검색·메뉴·동의 UI가 깨지지 않는가.
- 캐시 버전 갱신 후 실제 운영 환경에서 새 원고가 보이는가.

현재 제공된 검사 명령은 다음과 같다. 이는 향후 코드 반영 시 실행할 체크리스트이며, 이 계획서에 적혔다는 이유로 실행 완료를 뜻하지 않는다.

```sh
npm ci
npm run lint:html
python -B scripts/check_seo.py
python -B -m unittest discover -s scripts -p "test_*.py"
npm run test:unit
npx playwright install chromium
npm run test:browser
```

사이트맵 페이지 수가 늘면 21페이지·14제품 등 현재 가정을 의도에 맞게 검토한다. 실패를 없애기 위해 검사만 느슨하게 바꾸지 않는다. 제품 수가 유지된다면 14종 확인은 계속 유지한다.

제품 URL을 바꿔야 할 경우에만 이전→새 URL 목록, 서버 측 영구 리디렉션, canonical·내부 링크·사이트맵 갱신을 함께 처리한다. 현재 GitHub Pages에서 필요한 리디렉션을 어떻게 제공할지 먼저 결정한다. [Google URL 변경 안내](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)

## 12. 성과 확인 방법

설정·문구를 바꾸기 전에 접근 가능한 기존 데이터로 기준선을 기록한다. Search Console 등록 자체, 크롤링 허용, 구조화 데이터 존재를 성과로 계산하지 않는다.

| 측정 대상 | 기록할 것 | 해석 주의 |
|---|---|---|
| Google 검색 | 페이지 색인, 검색어·페이지별 노출·클릭·CTR·평균 게재순위 | 브랜드명 검색과 일반 성분/제품 선택 검색 구분 |
| 사이트 방문 | GA4 방문·주요 페이지·외부 판매처 클릭 | 동의·차단 때문에 전체 방문이 모두 수집되지 않음 |
| 판매 연결 | Amazon Attribution 등 실제 제공되는 보고서 | 외부 클릭은 구매가 아님 |
| AI 답변 | 서비스·날짜·언어·검색 사용 여부·동일 질문·언급 제품·인용 URL·설명 정확성 | 언급, 자사 URL 인용, 실제 추천을 별도 기록. 단일 답변은 전체 성과가 아님 |

시범 질문은 브랜드 질문과 일반 질문을 나눈다. 예: `CELDYQUE PDRN 제품의 차이`, `PDRN 세럼과 크림 선택 기준`, `PDRN 제품 추천`, `Volufiline 사용법`. 영문 사이트의 목표를 평가할 때는 영문 질문도 포함하고 국가·언어 조건을 기록한다. 검색 기능이 없는 AI 답변은 웹페이지 변경 효과와 분리해서 본다.

충분한 관찰 기간과 검색 노출량을 확보해 같은 조건으로 비교한다. 자료 정확성·관련성·근거·탐색을 개선하되, 특정 AI 순위나 기간 내 성과를 약속하지 않는다. 이 문서는 향후 측정 계획이며 반복 실행 자동화를 생성하지 않았다.

## 13. 작업 시작 순서

1. 현황 MD에서 14제품 원문을 제품별 기준 정보로 옮기고 모두 `imported` 상태로 시작한다.
2. PDRN 3종의 성분·농도·사용법 충돌을 먼저 질문 목록으로 만든다.
3. 받은 자료를 항목별 대조해 근거와 확인 상태를 기록한다.
4. PDRN 3제품 원고와 비교 가이드 초안을 같은 기준 정보에서 작성한다.
5. 이 형식이 제품 관리에 적합한지 확인하고 나머지 11제품으로 확장한다.

첫 다음 결과물은 **14제품 기준 정보 초안, 미확인·충돌 항목 목록, PDRN 3종 비교 원고**다. 현재 현황 문서의 원문 아카이브는 변경 전 기록으로 남기고, 새 원고와 혼합하지 않는다.
